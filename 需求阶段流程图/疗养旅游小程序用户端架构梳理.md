# 疗养旅游小程序用户端架构梳理

> 基于当前拿到的用户端截图与业务描述整理。  
> 业务核心：集团统一给员工发放虚拟积分，员工使用积分在平台内兑换疗养旅游、健康检测、医保理赔、用药等服务，并参与旅游团或消费权益。

---

## 1. 项目定位

该小程序是一个面向集团员工的「福利积分兑换 + 疗养旅游服务」平台。用户不是普通 C 端游客，而是集团内部或合作单位员工，平台的核心价值不是单纯售卖旅游产品，而是承接集团福利、疗养权益、员工健康服务与积分消费闭环。

用户端主要承担：

1. 展示集团可兑换的疗养旅游与健康服务项目。
2. 展示员工个人积分、卡券、权益额度。
3. 支持员工按目的地、主题、项目类型筛选疗养项目。
4. 支持用户报名、兑换、成团、出行、评价、退款/退单等流程。
5. 提供检测报告、服务指南、客服、规则中心等配套服务。

## 3. 底部导航结构

从截图看，项目内至少存在两套底部导航。

### 3.1 平台主导航

适用于平台首页、积分页、我的页。

```text
首页 / 积分 / 我的
```

| 导航 | 作用 |
|---|---|
| 首页 | 展示平台整体服务，包括疗养、检测、理赔、用药等入口。 |
| 积分 | 展示用户积分余额、可兑换卡券、权益有效期。 |
| 我的 | 展示用户资料、订单、报告、评价、客服、规则等个人中心功能。 |

### 3.2 身心休养子模块导航

适用于进入「身心休养」后的二级业务空间。

```text
首页 / 行程 / 权益
```

| 导航 | 作用 |
|---|---|
| 首页 | 身心休养项目浏览、搜索、推荐、分类入口。 |
| 行程 | 查看用户报名后的旅游团状态与退单记录。 |
| 权益 | 查看身心休养权益、可用卡券、兑换资格、剩余额度等。 |

这里可以理解为：平台主首页是总入口，而「身心休养」是一个相对独立的业务频道，进入后拥有自己的首页、行程和权益体系。

## 6. 用户端核心业务流程

## 6.1 积分兑换疗养项目流程

```text
集团发放积分 / 权益
        ↓
用户进入小程序
        ↓
查看积分余额 / 可用卡券
        ↓
进入身心休养模块
        ↓
按目的地 / 主题 / 搜索选择项目
        ↓
查看项目详情
        ↓
确认使用积分或权益
        ↓
提交报名 / 兑换订单
        ↓
等待成团
        ↓
成团后等待出发
        ↓
行程中
        ↓
行程完成
        ↓
评价 / 售后
```

## 6.2 行程状态流转

```text
待支付
  ↓
待成团
  ↓
待出发
  ↓
行程中
  ↓
已完成
  ↓
待评价 / 已评价
```

异常流程：

```text
待成团 / 待出发
  ├─ 用户申请退单 → 退单中 → 退单成功 / 退单失败
  └─ 平台解散团 → 已解散 → 积分 / 权益退回
```

## 11. 用户端关键权限与校验

1. 未登录用户：可浏览首页，但进入积分、权益、报名、订单时需要登录。
2. 无集团身份用户：不能查看集团专属权益或兑换项目。
3. 积分不足：不能提交积分兑换订单。
4. 权益不可用：包括已过期、已使用、被冻结、非适用项目。
5. 项目已封团：不能报名。
6. 项目名额不足：不能报名，或进入候补流程。
7. 行程已开始：退单规则需要限制。
8. 行程已完成：开放评价入口。

## 14. 一句话总结

该用户端可以理解为一个「集团员工福利积分商城」与「疗养旅游报名系统」的结合体：平台首页负责承接多类健康福利服务，积分页负责展示用户福利资产，身心休养频道负责项目发现和报名，行程与订单模块负责服务履约，个人中心负责报告、评价、客服和规则等后续服务。
