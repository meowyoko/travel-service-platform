## 实施清单

### 1. 环境确认

- 只读检查本机是否已有 PostgreSQL、Docker、`psql` 及 5432 端口占用。
- 优先使用 PostgreSQL 18.4；若未来云数据库确定使用 17，则本地改用相同大版本 17.10。
- 不使用 PostgreSQL 19 Beta。当前 18.4 是正式稳定版，官方支持至 2030 年。[版本说明](https://www.postgresql.org/support/versioning/)

### 3. PostgreSQL 接入

采用：


Drizzle 原生支持 `node-postgres`，也方便以后配置云数据库 SSL 和连接池。[官方文档](https://orm.drizzle.team/docs/get-started-postgresql)

### 4. 数据库模型

建立完整一期表结构：

```text
operator_accounts
operator_page_permissions
groups
employees
quota_accounts
service_products
product_visible_groups
personal_intents
personal_orders
quota_transactions
service_reviews
sessions
```

关键类型：

- ID：`text`，兼容现有 Mock ID；新增数据使用 UUID 字符串。
- 金额/额度：`integer`。
- 时间：`timestamptz`。
- 出行日期：`date`。
- 商品扩展和订单快照：`jsonb`。
- 密码：`password_hash`，绝不返回前端。
- 唯一约束和外键全部在数据库落实。

只提交正式 migration，不依赖 `drizzle push` 作为生产流程。

### 5. 种子数据

- 从现有 `mockData` 一次性写入空数据库。
- 保留现有对象 ID 和关联关系。
- 演示密码在写入前转换为 `scrypt` 哈希。
- Seed 可重复执行：已有初始化标记时拒绝重复插入。
- 不在 API 启动时自动重置数据库。

### 6. 真实认证

接口：

```text
POST   /api/admin/session
GET    /api/admin/session
DELETE /api/admin/session

POST   /api/employee/session
GET    /api/employee/session
DELETE /api/employee/session
```

规则：

- Session Token 使用安全随机值。
- 数据库只保存 Token 哈希。
- Cookie 使用 `HttpOnly`、`SameSite=Lax`。
- 生产环境开启 `Secure`。
- 停用账号不能登录。
- `/session` 响应不包含密码、内部备注等字段。
- 管理端和员工端身份不可混用。

### 7. 基础接口

```text
GET /api/health
```

响应只包含：

```json
{
  "status": "ok",
  "database": "connected"
}
```

不泄露数据库地址、版本和凭证。

### 8. 测试门槛

第一轮完成时必须通过：

- 全新数据库可完整执行 migration。
- Seed 后各实体数量与当前 Mock 一致。
- 数据库内不存在明文密码。
- 正确账号可登录，错误密码与停用账号被拒绝。
- 管理员 Cookie 不能访问员工身份接口，反之亦然。
- Session 可恢复、退出后立即失效。
- 数据库连接失败时健康检查明确失败。
- 现有 44 项测试继续通过。
- `typecheck`、`build`、`verify:mock` 全部通过。
